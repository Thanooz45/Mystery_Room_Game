# Casefile — AI Mystery Room

The canonical product and implementation requirements are in [`SPEC.md`](SPEC.md).

Casefile turns a fictional scenario into a playable investigation. Users create an account, submit a story premise, inspect a generated case and its evidence, save private notes, accuse a suspect, and review the solution. The backend keeps the solution separate from the public case until the investigation is complete.

## Stack

- React, Vite, React Router, Tailwind CSS
- Express, MongoDB, Mongoose
- Gemini structured JSON generation (server only)
- Mongo-backed, HTTP-only sessions; bcrypt password hashing
- Difficulty-validated case generation, private hints, and backend-scored investigations

## Requirements

- Node.js 20 or newer
- MongoDB 6 or newer, local or managed
- A Gemini API key for case generation

## Run locally

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env` and set `MONGODB_URI`, `SESSION_SECRET`, and `GEMINI_API_KEY`. Use a random session secret of at least 32 characters. For local development, `COOKIE_SECURE=false` and `CLIENT_ORIGIN=http://localhost:5173` are appropriate.
3. Start MongoDB.
4. Run `npm run dev` and open `http://localhost:5173`.

The Vite development server proxies `/api` to Express using the `PORT` value in `.env` (5001 by default to avoid macOS Control Center's port 5000 listener). The API validates configuration at startup and will not start if required settings are missing. If the Gemini key is absent, account and history features remain available, but generation fails with a user-safe case status.

For copy/paste startup commands for macOS Terminal and Windows PowerShell, see [`start.txt`](start.txt). It uses Docker Compose for a local MongoDB instance.

## Production

The repository includes a multi-stage production [`Dockerfile`](Dockerfile) and [`compose.yaml`](compose.yaml). The container builds the frontend, installs production-only dependencies in the runtime image, runs as a non-root user, exposes a health check, and handles `SIGTERM`/`SIGINT` for graceful shutdown.

Use a managed MongoDB database in production. Set `MONGODB_URI`, `GEMINI_API_KEY`, `SESSION_SECRET` (unique, random, at least 32 characters), `CLIENT_ORIGIN` (the exact public HTTPS origin), and `COOKIE_SECURE=true` in `.env` or your host's secret manager. Set `NODE_ENV=production`; the compose file sets this for its container. Build and launch with `docker compose up -d --build`, then check `docker compose logs -f app` and `curl http://127.0.0.1:5000/api/v1/health`.

The app binds to `127.0.0.1:5000` on the host. Put a TLS reverse proxy or managed HTTPS ingress in front of it and forward traffic to that address. The production session cookie requires HTTPS. Configure the proxy to pass forwarded headers; the server trusts one proxy hop in production. Keep MongoDB private, use a least-privilege database user, and store production secrets in your platform's secret manager. Do not commit `.env` files or credentials. The local-only MongoDB service in `compose.local.yaml` is for development, not production.

The deployment must provide a durable MongoDB instance reachable by both Mongoose and the session store. Restrict database network access and use a least-privilege database user.

## Deploy the frontend to Vercel and the API to Render

This split is supported by the root [`vercel.json`](vercel.json) and [`render.yaml`](render.yaml). Vercel hosts the Vite build and proxies `/api/v1/*` to `https://mystery-room-game.onrender.com`, so browser requests remain on the Vercel origin and use the secure session cookie. API responses are marked `no-store` because case and session responses are user-specific. Vercel supports external-origin rewrites, while Render web services must listen on `0.0.0.0` and use the provided `PORT` value ([Vercel rewrite docs](https://vercel.com/docs/routing/rewrites), [Render web services](https://render.com/docs/web-services)).

1. Push this project to a GitHub repository. Do not commit `.env`.
2. In Render, create a Blueprint from the repository and use `render.yaml`. Provide `MONGODB_URI`, `GEMINI_API_KEY`, and `CLIENT_ORIGIN` when prompted. Set `CLIENT_ORIGIN` to the Vercel production URL you plan to use, such as `https://your-project.vercel.app`. `SESSION_SECRET` is generated by Render. The service uses `/api/v1/health` for its health check.
3. For MongoDB Atlas, use the Atlas connection string as `MONGODB_URI`, create a database user with only the permissions this app needs, and allow the Render service's outbound IP ranges in the Atlas IP access list. Render lists the service's outbound ranges in its dashboard; Atlas recommends allowing only the smallest required ranges and warns that `0.0.0.0/0` allows connections from anywhere ([Render outbound IPs](https://render.com/docs/outbound-ip-addresses), [Atlas IP access list](https://www.mongodb.com/docs/atlas/security/ip-access-list/)).
4. Wait for the Render service to deploy and copy its HTTPS origin, for example `https://casefile-api.onrender.com`.
5. Import the same GitHub repository into Vercel. Keep the project root at `/`; the root `vercel.json` configures framework Vite, build command `npm run build`, output directory `dist`, the Render API rewrite, and SPA fallback. No API-origin environment variable is needed with this configuration.
6. Deploy to Vercel. Confirm that its production URL matches `CLIENT_ORIGIN` on Render exactly, including `https://`. If the final Vercel domain differs, update Render's `CLIENT_ORIGIN` and redeploy the Render service.
7. Open `https://your-project.vercel.app/api/v1/health`; it should return a small JSON health response. Then register and generate a case on the Vercel site.

Do not add `GEMINI_API_KEY`, `SESSION_SECRET`, or `MONGODB_URI` to Vercel. They belong only in Render. Vercel preview deployments use different origins; the current API accepts one exact `CLIENT_ORIGIN`, so use the production Vercel URL for production, and configure a separate matching API environment if you need authenticated preview deployments.

The Render API must be publicly reachable by Vercel's proxy. Keep database access restricted separately through Atlas networking and credentials. Render's current platform supports Git-backed web services and HTTPS; use the dashboard to confirm deployment health and logs ([Render health checks](https://render.com/docs/health-checks)).

## API overview

Base path: `/api/v1`

- `GET /health`
- `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`
- `POST /cases` (requires `Idempotency-Key`), `GET /cases`, `GET /cases/:caseId/status`, `GET /cases/:caseId`
- `PUT /cases/:caseId/progress`, `DELETE /cases/:caseId`
- `POST /cases/:caseId/evidence/:evidenceId/discover`
- `POST /cases/:caseId/hints`
- `POST /cases/:caseId/accusation`, `GET /cases/:caseId/result`

All case routes require an authenticated session and enforce ownership. Public case responses contain no private solution or unrequested hints. Difficulty fixes the suspect/clue/hint counts at easy 3/5/2, medium 4/7/3, and hard 5/9/3. The backend validates these counts, records clue discoveries and hint usage, and calculates the final score (correct-accusation base of 100/150/200, +5 per discovered clue, −10 per hint, minimum zero). The result endpoint is unavailable until the case is completed.

## Mystery generation

The server calls Gemini with a constrained JSON schema prompt, validates the response with Zod, checks exact difficulty counts and cross-references, and only then marks the case ready. Generation runs asynchronously after the API acknowledges case creation. Transient/provider or validation failures are bounded by `GENERATION_MAX_ATTEMPTS`; failed cases receive a safe status code. Generated evidence is explicitly fictional and does not fetch remote images or real communications.

## Data and privacy

User narratives, generated investigations, progress, and sessions are stored in MongoDB. Passwords are bcrypt-hashed; session cookies are HTTP-only, SameSite=Lax and secure in production. Solutions are stored separately and selected only by the result route. Users can access and delete only their own cases.
